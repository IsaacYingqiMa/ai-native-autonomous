# zsspec · AI 原生规格驱动研发技能包

> **一条链走完一个变更**：init（接入一次）→ spec（契约：需求/规格/设计）→ plan（任务卡清单）→ apply（开发+验证+回写）→ archive（沉淀/归档）。全程不碰 git 提交——代码提交由你自行决定。
> 默认逐阶段推进：人提需求、答阻断性问题、说"继续"走下一步；明确说"自主推进 / 自动走完"等授权后，全自动串联到底（授权到本变更收口止）。每阶段输出三行简报，透明、可随时打断。

**版本 v2.0**

## 30 秒看懂

```
[一次性] /zsspec-init —— specs/ 骨架 + 知识底座
                     ↓
每个变更（默认说"继续"推进；授权自动模式后串联到底）：
  1. /zsspec-spec     契约：需求 → 关键决策确认 → 边界 → 规格 → 设计
     （含糊 / 方向决策 → 选择题式提问，带推荐项）
  2. /zsspec-plan     任务卡：组 = 冲突域；卡 = 描述 / 步骤 / 预期 / 验收
  3. /zsspec-apply    公共组串行先行 → 无交集组并行（≥3）→ 验收回填
     （失败三级：T1 自愈 → T2 提问 → T3 中止）
  4. /zsspec-archive  知识沉淀 → 归档 → 验收汇总（全程不碰 git 提交）
                     ↓
              回到空闲，知识层已更新
```

## 五个技能（职权唯一、各自独立自包含）

| 技能 | 定位 | 只写 | 禁止 |
|---|---|---|---|
| `zsspec-init` | 一次性初始化 | specs/ 骨架、MAP/INDEX、知识底座 | 生成 spec/plan；改代码 |
| `zsspec-spec` | 契约：需求 + 规格（规则/用例/验证行）+ 设计 | spec.md | 一切其他文档与代码 |
| `zsspec-plan` | 任务卡清单（组 = 冲突域） | plan.md | 一切其他文档与代码 |
| `zsspec-apply` | 按卡开发验证（串行 + 并行调度） | 设计清单范围内的代码与测试、plan 执行状态 | 改规格/用例；弱化断言；git 提交；写知识层 |
| `zsspec-archive` | 沉淀 + 归档（不碰提交） | modules/、MAP.md、INDEX.md、archive/ | git 提交；改代码与规格内容 |

每个技能目录自包含：产出文档的模板放在各自 `templates/` 下（spec/plan 各一份，init 管知识层三件 MAP / INDEX / module），随技能分发、全局单份——specs/ 运行时不产出任何模板副本，只有真实工件。

## specs/ 目录（项目内实际产物）

```
specs/
├── MAP.md                # 模块地图（职责 + 核心实体 + 依赖）
├── modules/<domain>.md   # 业务域知识（带代码位置 + 校准头）
├── active/<slug>/        # 进行中：spec.md + plan.md
└── archive/
    ├── INDEX.md          # 变更总账
    └── <slug>_<日期>/    # 归档
```

## 日常速查

| 意图 | 输入 |
|---|---|
| 提新需求 | `/zsspec-spec 开发XX` 或直接说"开发XX"——**随时可提，已有未完成变更也不挡**（多变更并行，模块重叠时软提示） |
| 要测试锁定 | 提需求/评审时点名"XX 要测试" |
| 继续推进 | 说"继续"（多个变更时列清单让选，或点名"继续 <slug>"） |
| 全自动推进 | 说"自主推进 / 自动走完 / 不用逐步确认"（授权到当前变更收口，可随时收回） |
| 回答阻塞 | 按阻塞块选择题回答（如"选 a"） |
| 打断纠偏 | 直接说，处理完说"继续" |
| 放弃变更 | 说"放弃 <slug>" |
| 复盘 | 读 archive/INDEX.md → 进 `<slug>_<日期>/` |

## 设计铁律

**AI-Native 总纲：AI 写码便宜、上下文与验证贵——spec 出题（验证行）、apply 答题（执行核验回填），证据按风险付费，能并行不串行，文档每个字段都被下游消费。**

1. **spec 是完整契约，也是出题人**：需求 / 边界（为什么、范围）+ 规格（做什么 / 规则（触发→结果）/ 用例（可选，预期精确化）/ **验证行**）+ 设计（apply 改动边界）。验证四写法按性质选：构建（静态）、**运行核验（行为逻辑默认）**、测试（**仅用户点名或核心资产**）、达标（调优）；规则含分支/校验逻辑的验证不得只写构建。
2. **决策不静默拍板，修改优先**：影响规格走向且无唯一答案的决策由用户拍板——默认模式批量抛选择题（选项 + 推荐项置首附理由），自动模式按推荐项拍板、落档取舍、报告自主拍板清单，文档不留"待定"；需求变更默认修改既有文件（先读知识层/代码再定位），新增模块仅限全新业务能力或经论证的失衡——绕开旧实现另起一套 = 重复实现 + 僵尸代码。
3. **plan 是任务卡清单**：每卡四层（描述 / 步骤（可选）/ 预期（可判定、与 spec 验证行同源）/ 验收（apply 回填实际观察））+ 状态（任务勾选 + 组头三态）；组 = 冲突域供并行调度。
4. **apply 答题不发明题**：按卡执行、一致才勾选、验收回填具体观察（禁"通过"二字）；**TDD 只是测试任务的步骤写法**——断言照抄用例表、先跑出断言失败再实现到全绿，其余任务直接实现 + 核验；公共文件组先行，无交集组并行派发子代理（目标 ≥3），plan.md 单写者 = 主线程、回写前复跑核实；失败三级自愈（T1→T2→T3）组间隔离。
5. **阶段报告是通报不是审批**——默认每阶段报告后停（说"继续"进下一步）；授权自动模式后报告即流转到底，仅阻断性信息缺口（需求含糊 / 关键决策 / 冲突裁决 / 阻塞提问）才需要你作答。
6. **archive 是知识层唯一运行期写入者，只写当前状态不写历史**；证据可复现替代人工盖章（回归绿 = 收口前提，INDEX = 审计面）；**全流程不执行 git 提交**——提交由用户自行决定。
7. **异源校验按风险触发，不无差别摊派**：spec 盲推对照仅规格 >5 条时做；并行时主线程复跑 + 抽查；回归 = **重放验证**（构建 + 用例重放 + 测试），不是只跑测试套件。

## 安装

把本仓库 `.claude/skills/` 下 5 个技能目录完整拷入目标项目（含各自 `templates/` 模板，缺失则技能会拒绝产出），CLAUDE.md 内容并入目标项目根目录，然后 `/zsspec-init`。
