# zsspec-apply · 按任务卡开发（串行 + 并行调度）

决策来源：任务与预期 = plan.md 任务卡，实现方案与改动范围 = spec「设计」，判定锚点 = 卡「预期」（对齐 spec 用例）；勾选即进度，恢复 = 从第一个未勾任务继续。

> AI-Native 原则：能并行不串行（组 = 冲突域，无交集即并发）；验收回填实际观察（可核查的具体现象，禁只写"通过"）；plan.md 单写者 = 主线程，子代理只做不改档。

## 职权

| 边界 | 内容 |
|---|---|
| 只写 | spec「设计」清单结构范围内的代码与测试 + 支撑性小改（辅助文件/配置/类型声明，验收行申报）；plan.md 执行状态（勾选、验收回填、组头状态、「阻塞」块、「完成」块） |
| 只读 | plan.md、spec.md（设计、规则与用例）；验证失败且怀疑规格时按所在组号 Sx 回读规格条款 |
| 越界去向 | 改 spec.md 条款或用例表 → zsspec-spec 修订模式；改任务描述/预期/回归范围 → 阻断性提问，裁决后走 zsspec-plan 修订模式；写 modules → zsspec-archive |
| 并行约束 | 派发的子代理受同样职权约束，且**额外禁止**写 plan.md / spec.md / 知识层文件——子代理只交代码与验收文本，进度回写一律由主线程做 |

<HARD-GATE>
1. 决策唯一来源是 plan.md：禁止改任务描述、预期、回归范围。
2. 实际与预期一致才勾选；验收行回填**具体观察**（现象/输出/判定，如"空提交 → 三项红字提示"），禁止只写"通过/成功"。
3. **测试任务（步骤含"转写用例"）**：断言照抄 spec 用例表（一用例一测试），禁止增删断言、改期望值或弱化语义来凑通过；先跑出**断言失败**（防用例恒真，语法/收集/环境错误不算）再实现到全绿。发现用例本身有错 → 停，走 zsspec-spec 修订模式改用例表。
4. 失败禁止盲改与同假设重试：T1 每任务最多 3 次、每次基于新假设（动手前记「假设：失败因为 X」），仍不通升 T2/T3。
5. **并行核实**：子代理报告的结果不算数，主线程复跑该组验证一致后才勾选；plan.md/spec.md 唯一写者 = 主线程。
</HARD-GATE>

## 入口判定（按当前变更 plan.md 状态，从上到下首条命中；当前变更定位 = active/ 唯一未完成变更，多个时用户点名或列出清单——slug + 一行进度——让用户选，新需求不在本技能处理）

| plan.md 状态 | 行为 |
|---|---|
| 「阻塞」块有待答问题 | 复述问题请用户回答 → 按答案处理、清除阻塞块、从该任务继续 |
| 有未勾选任务 | 从**第一个未勾任务**继续（勾选即进度，天然防重复执行）；进入「执行模式判定」 |
| 全部勾选但「完成」块未填 | 幂等补做收尾：按「全量回归与收尾」回填完成块（不重跑任务） |
| 全部勾选且「完成」块已填（出现非注释内容即视为已填） | 自动模式 → 进入 zsspec-archive（幂等）；默认 → 回复"任务已全部完成，说'继续'进入收口（zsspec-archive）" |

**旧版计划兼容**：无四层任务卡结构的旧计划（任务行 + 验证行 / 档位组头）→ 照旧按既有任务行执行与勾选（任务行验证命令照跑、T 档红绿照走），不重写既存 plan。

## 执行模式判定（入口命中"有未勾任务"后先做，产出本轮执行序）

1. 读 plan 未勾组 + spec「设计 · 模块与接口」清单，为每组标注涉及文件（该组测试文件 + 设计清单中该规格相关文件）
2. **公共文件组先行（串行段）**：P 组，以及涉及"被 ≥2 个未勾组共同触及的文件"（路由表、全局布局、共享数据模块等）的组——这些组按「串行执行」逐个做完
3. **并行批次（并发段）**：剩余组两两判文件交集——无交集的组构成可并行集；**可并行组 ≥2 即并行派发子代理，单批 ≤5、目标 ≥3**；不足 2 组或无法判定交集（保守视为有交集）→ 照旧串行
4. 执行序固定：串行段 → 并行批次（一批全回写后再派下一批）→ 回归组

## 串行执行（循环，单卡流程）

1. 读第一张未勾卡 → 按步骤（有步骤层）或按 spec「设计」直接实现 → 用卡「预期」对应的验证手段比对：
   - **构建/测试/达标**：跑命令比对判定
   - **运行核验**：把系统跑起来（dev/preview/脚本/请求），按 spec 用例逐条操作并观察现象
2. 一致 → 勾选 + 回填「验收」（具体观察，≤5 行不贴长输出；测试任务另含红灯证据，如"RED 确认：断言失败 ✓"）→ 刷新组头状态（全未勾 = 未开始 / 部分 = 进行中 / 全勾 = 已完成；与勾选不符时以勾选为准）→ 下一张卡
3. 任务通过后若改动可能波及其他模块 → 立即重放该模块既有验证（局部回归；全量回归在末项 R1）
4. 不一致 → 失败三级梯队：
   - **T1 自愈**（每任务 ≤3 次，每次动手前先记一行「假设：失败因为 X」，假设互不相同——换实现路径 / 读更多上下文 / 按所在组号 Sx 回查 spec 对应条款；三次假设全错 = 问题在理解层，直接升 T2）
   - **T2 阻断提问**（怀疑规格含糊或需求歧义）：「阻塞」块写 失败摘要 + 诊断 + **选择题式提问**，停止等回答。答案三选一：
     - 改实现 → 清除阻塞块，从该任务继续
     - 改规格（条款/用例表）→ zsspec-spec 修订模式落实；波及未勾任务卡时联动 zsspec-plan 对齐
     - 改任务卡 → zsspec-plan 修订模式落实
     - 修订落实后自动回本技能，从该任务继续
   - **T3 中止**（外部依赖不可用/环境故障）：「阻塞」块写 诊断 + 已试策略 + 建议处理方式，停止；用户处理后说"继续"

## 并行执行（可并行集 ≥2 组时替代逐组串行）

1. **派发**：同批每组一个子代理（单批 ≤5，目标 ≥3 组同时跑），一条消息内并行派发。子代理指令必须包含：
   - 该组任务卡原文 + spec 对应 Sx 条款（规则 + 用例表）+「设计」段 + 项目验证命令
   - 文件边界：只改该组涉及文件与其测试文件，公共文件与他组文件禁改
   - 执行要求：按卡自足执行（步骤含转写用例的照抄断言、先红后绿）；组内失败自行 T1（≤3 次，记假设），仍失败即整组返回失败摘要，禁止越界改他文件排障
   - 返回格式：每卡一行验收文本（具体观察 + 判定）+ 关键改动文件列表
2. **回写复核（逐组，全部通过才勾选）**：
   - ① 复跑：主线程重跑/重放该组全部验证，以**主线程结果**为准（不符 → 该组按失败处理）
   - ② 抽查：测试任务读测试文件确认断言与用例表逐条对应、无增删改语义；运行核验任务抽 1 条用例重放（发现偏离 → 修正后复跑）
   - ③ 通过 → 勾选 + 验收回填 + 组头刷新
3. **失败隔离**：某组失败（子代理报告失败/复跑不符/抽查偏离）→ 该组剩余任务回主线程按「串行执行」第 4 条三级梯队处理；同批他组已复核通过的结果不受影响
4. 批间推进：一批全部回写后再判定下一批（公共文件可能已被上一批改动，交集重算）

## 全量回归与收尾（末项任务，串行/并行两路共用）

R1 重放全部验证（构建全跑 + 运行核验重放 + 测试全跑）：不绿 → 按失败三级梯队处理；全绿 → 勾选 + 验收回填，回填「完成」块三项（时间、回归判定行、覆盖规格）——全程不做 git 提交，改动留在工作区。

## 门禁（收尾前逐项核对，全过才继续）

- [ ] 全部任务勾选且每卡验收已回填具体观察（无"通过"二字糊弄）
- [ ] 并行组均已过主线程复跑核实；测试任务断言与用例表逐条对应（无增删改）
- [ ] 「阻塞」块为"无"
- [ ] 完成块三项齐全
- [ ] 未改 spec.md、任务描述与预期；未弱化任何断言
- [ ] diff 自查：结构改动均在 spec「设计」清单内，清单外仅支撑性小改（辅助文件/配置/类型声明）且已逐项在验收行申报；无调试残留（console.log / print 调试输出等）；无新增 TODO/FIXME 遗留

## 上下文自察（软建议，不阻断）

已勾任务过半且会话已长（大量 diff/报错堆积）→ 报告提示"建议开新会话说'继续'——恢复 = 第一个未勾任务"，照常可继续推进。并行派发天然省主线程上下文（diff 在子代理内消化），优先用并行。

## 阶段报告

三行简报：**做了什么**（一两句：任务完成与回归判定；并行批次与组数）/ **需要注意**（T1 要点与遗留风险，无则"无"）/ **下一步**（建议进入 zsspec-archive：沉淀 + 归档）。
输出后：自动模式（用户已授权）→ 直接进入 zsspec-archive；默认 → 停，等用户说"继续"或指定技能。
