# zsspec-init · 项目接入初始化

一次性接入：目录骨架 + 知识底座。绝不预生成规格/计划类文档，不在 specs/ 产出任何模板类产物。

## 职权

| 边界 | 内容 |
|---|---|
| 只写 | `specs/` 目录骨架（modules/ active/ archive/）、`specs/MAP.md`、`specs/archive/INDEX.md`、历史项目 `specs/modules/*.md` |
| 只读 | 项目根结构、src/ 代码 |
| 越界去向 | 开发需求 → zsspec-spec；日常推进 → 主链路（plan / apply / archive） |

<HARD-GATE>
1. 禁止创建 spec.md、plan.md 或 specs/active/ 下任何内容——新项目杜绝预生成。
2. 禁止修改 src/ 与 tests/ 任何文件。
3. 知识资产每条契约必须附代码依据（file::symbol），无依据的删除或标「待确认」，禁止臆造。
4. 禁止把 AI 开发工具目录（`.claude/`、`.agents/`、`.workbuddy/` 等隐藏工具目录）当业务代码——它们不是业务域，不建模块、不写入 MAP、不作场景 B 依据。
</HARD-GATE>

## 流程

本技能模板在 `templates/` 下（MAP.md、INDEX.md、module.md），随技能目录分发；缺失 → 停止并提示"技能包不完整，请重新拷贝 zsspec-init 技能目录"，禁止凭记忆手写结构替代。

**场景判定（先于 A/B）**：只按「业务代码」判断——业务代码 = 应用/产品实现代码（`src/`、`app/`、`lib/`、服务入口等）。**仅排除 AI 开发工具/代理的隐藏配置目录**：`.claude/`、`.agents/`、`.workbuddy/`、`.continue/`、`.kiro/`、`.trae/`、`.vscode/`、`.idea/` 等（含其内部文件）——这些是开发工具链，不算业务代码、不参与场景 B 判定、也不作模块划分依据；其余目录/文件按实判定。全项目仅含工具目录 → **场景 A**；含业务代码 → **场景 B**。

**场景 A · 空项目（无业务代码或只有骨架）**
1. 建目录 `specs/{modules, active, archive}`
2. `MAP.md`：按 `templates/MAP.md` 建（HTML 注释不复制，定位说明 + 表头保留）
3. `archive/INDEX.md`：按 `templates/INDEX.md` 建（HTML 注释不复制，定位说明 + 表头保留）
4. 不建任何模块文件（无代码即无知识）

**场景 B · 历史项目**
1. 先完成场景 A 的 1-3
2. **按业务域识别模块**（模块是业务能力单元，不是代码目录；技术分层 controllers / services / utils 之类不建模块），识别策略按代码组织形态分派：
   - 目录已按业务域组织（目录名是业务名词）→ 目录即模块锚点，直接映射
   - 目录按技术分层横切 → 读路由 / 接口定义 / 数据模型，按业务域聚类（一个域的代码散在多层也聚合为一个模块）
   - **宁粗勿错**：划分不确定时取大业务域——粗划分只是 spec 多读几段，错划分会误导规格依据；细化留给后续变更（archive 门禁含按子域拆分条款）
3. 每个业务域按本技能 `templates/module.md` 结构建 `specs/modules/<domain>.md`（注释行不复制；校准头写 `> 校准：init · <当天日期>`；「代码」行如实列出该域代码位置——供校准对账与人工索引）
4. 汇总 `MAP.md`（一行一模块：职责 + 核心实体领域词 + 依赖模块，依赖从 import/调用关系提取，无则 —）
5. 划分不确定的域 → 在阶段报告「关键决策」栏列出划分方案与置信度供人纠偏（不阻断）；大仓库可分批或只建主干域，未覆盖留给 zsspec-spec 登「知识维护」

**module.md 结构**：唯一定义 = 本技能 `templates/module.md`（本技能建初稿、zsspec-archive 运行期更新共用；五段，无内容的段省略，契约必须附代码依据）。

## 门禁（收尾前逐项核对，全过才报告）

- [ ] `specs/` 三目录 + MAP / INDEX 就位，specs/ 内无模板副本等多余产物
- [ ] modules 为业务域划分（无技术分层目录冒充模块），每个模块「代码」行非空
- [ ] 契约均有依据或标「待确认」
- [ ] `specs/active/` 为空；未改动 src/ 与 tests/
- [ ] 场景判定正确：全项目无业务代码时未建任何模块（AI 开发工具目录未被误判为业务域）

## 阶段报告

三行简报：**做了什么**（一两句：目录与模块数）/ **需要注意**（划分取舍、建议抽查的模块，无则"无"）/ **下一步**（一次性动作到此结束、空闲等待需求；**例外**：用户本次会话已带开发需求 → 提示进入 zsspec-spec 处理，自动模式下直接进入，不丢弃）。
