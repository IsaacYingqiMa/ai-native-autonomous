# zsspec-archive · 知识沉淀与归档收口

知识资产的唯一运行期写入者；产出验收汇总，变更闭环。**全程不执行任何 git 提交**——git 仅作只读探测（status/log/diff），代码提交的时机、粒度与信息由用户自行决定。

## 职权

| 边界 | 内容 |
|---|---|
| 只写 | `specs/modules/*.md`、`specs/MAP.md`、`specs/archive/INDEX.md`、`specs/archive/`（含 mv active/&lt;slug&gt;/） |
| 只读 | spec.md、plan.md、本次代码改动、受影响 modules |
| 越界去向 | 改 src/tests/spec.md/plan.md 内容 → 禁止（要改 = 未完成，回 zsspec-apply） |

<HARD-GATE>
1. 提炼增量的每条内容必须有依据（spec / plan 结果行 / 代码 diff），禁止臆造契约或陷阱。
2. 只写当前状态不写历史；「已知陷阱」合并去重。
3. 准入不通过禁止任何写入。
4. **不执行任何 git 提交**（git 仅 status/log/diff 只读探测）——代码提交由用户自行决定。
</HARD-GATE>

## 准入与幂等

当前变更定位 = active/ 唯一未完成变更；多个时用户点名或列出清单（slug + 一行进度）让用户选。

| 检查 | 不满足时 |
|---|---|
| active/<slug>/ 已不存在 | 不走准入报错——先按下方幂等第二条判定是否归档已完成 |
| plan.md 全勾 + 「阻塞」为"无" + 完成块已填 | 回复"计划未完成，请说'继续'由 zsspec-apply 推进" |

幂等（中断重入安全，按序判定）：
- INDEX 已含本 slug 行 → 跳过追加；modules 覆盖写天然幂等
- archive/ 已有 `<slug>_<日期>/` 且 active/ 已无该 slug（多变更并存时其他变更不受影响）→ 归档已完成，直接结束
- 其余中断态 → 重新走流程（覆盖写幂等、INDEX 未追加则追加、归档移动未做则补做）

## 流程

1. 圈定受影响模块 = spec「受影响模块」∪ 实际代码改动触及的模块（git 项目以 `git status --porcelain` 列出的改动文件对照各 module「代码」行判定；非 git 以 spec「设计」模块清单为准）——**改动触及而 spec 未列的模块同样要更新**
2. 提炼增量（对每个受影响模块）：
   - 新增/变更的接口契约（含成功与失败路径）
   - 新增/变更的状态机、关键约束、配置项、模板
   - 本次踩到的陷阱（从失败记录与 T1 尝试提炼）
   - spec「记录 · 知识维护」逐条处理：修正（modules 与代码不符，含流程外变更差异，优先）/ 补建（module 结构的唯一定义 = zsspec-init 技能的 `templates/module.md`）
3. 章节级覆盖写 modules：只重写涉及章节，未涉及章节保留原文；**刷新校准头为 `> 校准：<slug> · <归档日期>`**
4. MAP 同步：涉及模块的职责/核心实体/依赖有变化则更新对应数据行；新模块加行、废弃模块移除（头部定位说明保留不动）
5. INDEX 追加一行数据（列名同模板表头：完成日期 / slug / 摘要 / 模块 / 状态；头部定位说明保留不动）→ mv `active/<slug>/` → `archive/<slug>_<当天日期>/`（统一用 mv，不动 git 暂存区）→ 确认该 slug 已不在 active/（其他并存变更不动）

## 门禁（写入后逐项核对）

- [ ] 模块粒度合适：单文件承载多个业务域时按子域拆分并同步 MAP；表述可精简，事实不删
- [ ] 受影响模块全部更新且校准头已刷新
- [ ] 该 slug 已不在 active/（多变更并存时其余变更原样保留）；INDEX 有且仅有一行本 slug（含模块列）

## 阶段报告（验收汇总）

**规格覆盖表**：

| 规格 | 覆盖任务 | 验收命令 | 结果 | 依据 |
|---|---|---|---|---|

（Sx → 任务 → 命令 → 判定行）

三行收束：**做了什么**（一两句 + 规格覆盖表）/ **需要注意**（知识沉淀清单：更新的模块与章节、补建的缺口、修正项、新增陷阱，无则"无"）/ **下一步**（空闲，等待下一个需求）。

## 废弃分支

用户显式说"放弃 <slug>"：INDEX 追加行（状态 abandoned）→ mv 归档 → **不更新 modules 和 MAP**（未完成变更不沉淀知识）→ 确认该 slug 已不在 active/ → 提示两件事：① 工作区可能残留未提交的半成品代码，请自行处置（还原或另存）；② spec 中有价值的需求分析可自行留档。
